# 0.4.2 release

The v0.4.2 release integrates the reviewed feature work from the v0.4.2 milestone, centered on epic #11 (feature-demand research #10 and terminal UI research #31) plus the closed configuration [#14], P0/P1 contracts [#21], checkpoint services [#22], and Neovim pilot [#27] acceptance work.

Package and runtime versions are `0.4.2`. After merge into `main`, successful push CI triggers PyPI publication and creates tag `v0.4.2` on the tested merge commit.

## Key deliverables

### Configuration and settings (#14)
- Typed terminal UI controls (`ui.output_mode`, `ui.reduced_motion`, `ui.detail_density`, `ui.keyboard_mode`, `ui.mouse_capture`, `ui.layout.compact_tables`) with field-attributed validation and local import/export sync round-trips.
- Exact decimal money inputs preserved through startup, scoped reads, CLI set, and explicit control import.
- Local file transfer with explicit usage/operation/verification control export/import.
- Live settings snapshots retained by REPL and Textual for `/config view|get` and `/doctor`.

### P0/P1 schema and client compatibility (#21)
- All five provider adapters expand supported local references into detached request schemas.
- Registry-wide tool contracts with immutable schema snapshots and local result validation.
- Bounded schema meta-validation cache with offline profiling.
- MCP catalog and result fidelity with bounded pagination and typed results.

### Checkpoint services (#22)
- Content checkpoint foundation with before/after capture, revision-bound review, conflict-checked restore, and private retention.
- CLI and interactive `/checkpoint` commands share review, preview, apply, recovery, and retention.
- Windows NTFS content-only backend with completed native service regressions.

### Neovim pilot (#27)
- Opt-in v1 editor protocol over POSIX pipes with shared one-run authority.
- Neovim 0.4.2/Linux pilot for inspect/edit/check/review and denial.

### Usage and budgets (#24)
- Provider usage and explicit pricing with compatible and Anthropic adapters.
- Caller-owned API budgets with isolated process runs and durable SQLite accounting.
- Automatic task budgets shared across delegation, summaries, and continuations.

### Dynamic agents and delegation
- Default-off `agents.allow_delegation` startup opt-in with shared runtime admission capacity.
- Bounded delegation across dynamic, named, nested, and parallel routes.
- Plan-mode transition authority with `plan_mode_origin` persistence and operation-effect classification.

### Privacy and credential handling (#20)
- Shared credential projection across session persistence, exports, metrics, logs, and diagnostics.
- Verification evidence privacy with sensitive checks unavailable after rotation.

### Terminal UI (Textual)
- Typed UI controls wired into the TUI with startup application.
- F8 checkpoint review, F9 saved-input queue, F10 pending-decision inspection, F11 external-editor composition.
- Context/usage inspection with bounded read-only views.

### Evaluation and CI
- Evaluation registry with twelve independent coding scenarios and typed metadata.
- Supported CI matrix on Python 3.11–3.14 with installed-wheel smoke on Linux, macOS, and Windows.
- Release qualification requiring installed wheel and source-archive checks with matching receipts.

## Removed

- The `.agent_tasks/` workspace convention is removed from all agent instructions, docs, prompts, and tests.

## Remaining work

Final release qualification, broader UI/native accessibility qualification, and hosted model qualification remain tracked separately and are not part of this release.

## Validation

Repository-wide Ruff and Mypy checks pass. The release workflow validates both distribution archives with installed-wheel smoke checks before publication.
