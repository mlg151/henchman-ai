## Integration checks

The normal CI workflow runs for pushes and pull requests targeting both `main` and `0.4.1`.

- Run focused pytest, Ruff, and mypy checks for changed implementation areas.
- Review each issue's acceptance criteria and update its development evidence and PR link.
- Resolve integration conflicts and run the combined regression checks before marking the release PR ready.
- Keep unimplemented protocol adoption phases explicitly open in the standards roadmap.

Creating the staging and issue PRs does not publish a release or change the installed version. Release versioning and publication occur after integration review.

## Current validation

After including current main's CI fixes, issue #1 has 140 passing execution/formatting/prompt checks; issue #2 has 2,073 passing agent/config/contract/lifecycle/tool checks with no exclusions, focused frontend checks, and all 12 offline five-adapter coding-loop cases passing; issue #3 has 97 passing MCP/schema/documentation/packaging/API checks plus source-link/navigation validation. The subsequently merged CI PR #4 updates those test contracts and default test credentials; refreshed checks now pass without exclusions. The issue branches are not merged into staging yet; the release PR stays a draft pending their review, conflict resolution, combined validation, and release-version preparation.
