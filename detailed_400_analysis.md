# Detailed Analysis of 400 Error in Henchman AI Agent

## Problem Statement
The user received a 400 error from the OpenAI API while testing the henchman agent:
1. First error: "Messages with role 'tool' must be a response to a preceding message with 'tool_calls'"
2. Second error: "An assistant message with 'tool_calls' must be followed by tool messages responding to each 'tool_call_id'. (insufficient tool messages following tool_calls message)"

## Root Cause Investigation

### 1. Message Sequence Requirements (OpenAI API)
Based on OpenAI's API documentation:
- **Tool messages** (role: "tool") must:
  - Have a `tool_call_id` that matches a tool call ID from the immediately preceding assistant message
  - Come immediately after an assistant message that contains `tool_calls`
  - Not appear without a preceding tool call request

- **Assistant messages with tool_calls** must:
  - Be followed by tool messages for EACH tool call ID
  - Have tool messages in the correct order (matching the tool call order)

### 2. Code Analysis

#### Agent Class (`agent.py`)
Key methods for tool handling:

**A. `submit_tool_result(tool_call_id, result)` (lines 116-123):**
```python
def submit_tool_result(self, tool_call_id: str, result: str) -> None:
    """Submit a tool result.
    
    Args:
        tool_call_id: The ID of the tool call this result is for.
        result: The result from the tool execution.
    """
    self._pending_tool_results[tool_call_id] = result
```
- Stores tool results in `_pending_tool_results` dictionary
- Does NOT add to history immediately

**B. `continue_with_tool_results()` (lines 95-114):**
```python
async def continue_with_tool_results(self) -> AsyncIterator[AgentEvent]:
    """Continue execution after tool results have been submitted.
    
    This should be called after submit_tool_result() to continue
    the conversation with the tool results.
    
    Yields:
        AgentEvent objects as the agent continues processing.
    """
    # Add tool results to history
    for tool_call_id, result in self._pending_tool_results.items():
        self.history.append(
            Message(role="tool", content=result, tool_call_id=tool_call_id)
        )
    self._pending_tool_results = {}
    self._pending_tool_calls = []
    
    # Continue streaming
    async for event in self._stream_response():
        yield event
```
- Adds ALL pending tool results to history at once
- Clears pending results after adding to history
- Then calls `_stream_response()` to continue

**C. `_stream_response()` - Tool Call Handling (lines 158-171):**

### 3. Potential Issues Identified

#### Issue 1: History State Between Tool Call and Tool Result
When a tool call is made:
1. Assistant message with tool calls is added to history immediately
2. Tool results are NOT added to history until `continue_with_tool_results()` is called

This creates a window where the history contains an assistant message with tool calls but NO corresponding tool messages.

#### Issue 2: Multiple Tool Calls Handling
If an assistant message has multiple tool calls:
- All tool calls are added to history at once
- But tool results might be submitted one at a time
- The API expects tool messages for ALL tool calls before continuing

#### Issue 3: Tool Call ID Management
The code assumes tool call IDs are managed correctly, but:
- Tool call IDs are generated by the provider/LLM
- Must be preserved exactly when submitting results
- Mismatched IDs will cause 400 errors

### 4. Reproduction Scenario

Consider this sequence:
1. User: "List files"
2. Assistant: (with tool call for "ls")
   - History: [user, assistant(with tool_calls)]
   - `_pending_tool_calls` = [tool_call]
3. Tool execution happens (outside agent)
4. `submit_tool_result(tool_call_id, result)` is called
   - `_pending_tool_results[tool_call_id] = result`
5. BEFORE `continue_with_tool_results()` is called:
   - History still has assistant with tool_calls but no tool message
   - If any operation reads history (e.g., compaction, context loading), it's invalid

### 5. The Actual Bug

Looking at the error messages and code:

**First error**: "Messages with role 'tool' must be a response to a preceding message with 'tool_calls'"
- This suggests a tool message was sent without a preceding assistant message with tool_calls
- OR the assistant message was somehow removed/modified

**Second error**: "An assistant message with 'tool_calls' must be followed by tool messages responding to each 'tool_call_id'"
- This suggests an assistant message with tool_calls exists in the messages sent to the API
- But not all tool calls have corresponding tool messages in the sequence

### 6. Likely Culprit: Context Compaction

In `agent.py`, line 71-73:
```python
# Apply automatic compaction if context is too large
from henchman.utils.compaction import ContextCompactor
compactor = ContextCompactor(max_tokens=self.max_tokens)
return compactor.compact(messages)
```

The `ContextCompactor` might be:
1. Removing or modifying messages during compaction
2. Not preserving the strict tool call → tool message sequence
3. Breaking the OpenAI API requirements

### 7. Immediate Fixes Needed

1. **Fix Context Compaction**: Ensure compaction preserves tool call sequences
2. **Validate Message Sequences**: Add validation before sending to API
3. **Improve Tool State Management**: Better handling of pending tool calls/results
4. **Add Debug Logging**: Log message sequences before API calls

### 8. Recommended Implementation

```python
def validate_message_sequence(messages: list[Message]) -> None:
    """Validate that the message sequence follows OpenAI API rules."""
    for i, msg in enumerate(messages):
        if msg.role == "tool":
            # Must have preceding assistant with tool_calls
            if i == 0:
                raise ValueError("Tool message cannot be first message")
            prev_msg = messages[i-1]
            if prev_msg.role != "assistant" or not prev_msg.tool_calls:
                raise ValueError("Tool message must follow assistant message with tool_calls")
            
            # Tool call ID must match
            tool_call_ids = [tc.id for tc in prev_msg.tool_calls]
            if msg.tool_call_id not in tool_call_ids:
                raise ValueError(f"Tool call ID {msg.tool_call_id} not found in preceding tool calls: {tool_call_ids}")
        
        if msg.role == "assistant" and msg.tool_calls:
            # Check if followed by tool messages for all tool calls
            tool_call_ids = [tc.id for tc in msg.tool_calls]
            next_idx = i + 1
            while next_idx < len(messages) and messages[next_idx].role == "tool":
                tool_call_ids.remove(messages[next_idx].tool_call_id)
                next_idx += 1
            
            if tool_call_ids:
                raise ValueError(f"Assistant tool calls missing tool responses: {tool_call_ids}")
```

## Conclusion
The 400 error is caused by invalid message sequences being sent to the OpenAI API. The most likely cause is the context compaction logic not preserving the strict tool call → tool message sequence required by the API.
