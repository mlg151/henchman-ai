## How to Use the Metrics Dashboard

### 1. Accessing Metrics
```python
from henchman.agents.orchestrator import Orchestrator
from henchman.providers.deepseek import DeepSeekProvider

# Create orchestrator
provider = DeepSeekProvider(api_key="your-key")
orchestrator = Orchestrator(default_provider=provider)

# Run a task
async for event in orchestrator.run("Implement feature X"):
    # Process events...

# Get metrics report
report = orchestrator.get_metrics_report()
print(report)
```

### 2. Metrics Tracked

#### Efficiency Metrics (Automatically tracked)
- **Task Completion Time**: Start/end timestamps and duration
- **Files Accessed**: Which files were read/written and how many times
- **Tool Usage**: Breakdown of tool calls by type
- **Delegation Rate**: Percentage of tasks delegated vs. executed directly

#### Quality Metrics (Requires integration)
- **Test Results**: Pass/fail counts from test runs
- **Code Coverage**: Coverage percentage (requires coverage tool integration)
- **Linting Status**: Error/warning counts (requires lint tool integration)
- **Documentation Coverage**: Percentage documented (requires analysis)

#### Target Performance Metrics (Calculated)
- **File re-reads**: Calculated from file access patterns
- **Delegation rate**: Compared against 40% target
- **Error rate**: Percentage of failed tool calls
- **Context window usage**: Estimated context usage (requires token counting)

### 3. Extending the Metrics System

The metrics system is designed to be extensible. To add new metrics:

1. **Add to Metrics TypedDict** in `orchestrator.py`:
```python
class Metrics(TypedDict, total=False):
    # ... existing metrics ...
    your_new_metric: float
```

2. **Initialize in `_reset_metrics_for_run`**:
```python
self.metrics["your_new_metric"] = 0.0
```

3. **Track in appropriate methods**:
```python
def _update_your_metric(self, value: float) -> None:
    self.metrics["your_new_metric"] = value
```

4. **Include in `get_metrics_report`**:
```python
report_lines.append(f"- **Your Metric**: {self.metrics['your_new_metric']}")
```

### 4. Integration Points for Quality Metrics

To fully populate quality metrics, integrate with:

- **Test Results**: Hook into `pytest_run` tool results
- **Code Coverage**: Parse coverage reports from `coverage_map` tool
- **Linting Status**: Parse lint results from `lint_check` tool
- **Documentation Coverage**: Analyze docstrings with `python_ast` tool

### 5. Backward Compatibility

The extended metrics system maintains full backward compatibility:

- Existing `Metrics` TypedDict fields preserved
- All new metrics are optional (using `total=False`)
- Existing code using `orchestrator.metrics` continues to work
- New metrics initialized with sensible defaults

## Implementation Details

### Metrics Collection
- **Automatic**: Tool calls, file access, errors, thinking patterns
- **Semi-automatic**: Test results, linting status (requires tool integration)
- **Manual**: Documentation coverage, context window usage (requires implementation)

### Calculation Methods
- **File re-reads**: `total_accesses - unique_files`
- **Delegation rate**: `delegation_count / (total_tool_calls + delegation_count) * 100`
- **Error rate**: `failed_tool_calls / total_tool_calls * 100`
- **Test percentage**: `passing / total * 100`

### Performance Considerations
- Metrics tracking adds minimal overhead (incrementing counters)
- File access tracking uses dictionary lookups (O(1))
- Report generation only happens on demand
- Memory usage scales with unique files accessed
